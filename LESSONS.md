# Lessons

Distilled from `worklog/WORK_LOG.md` (chronological) + `worklog/FABLE_WORKLOG.md`. The headline case is pilot 11 (verus #2219), a soundness bug whose correct fix is an XOR-shaped predicate: detect where rustc *believes a value uninhabited* but the code does *not* actually diverge, while leaving genuine divergence alone.

## Scientific findings (verus #2219)

1. **Prompt-method engineering gives no lift.** Six prompt-encoded "methods of inquiry" (hypothesis-graph, bi/tri-abduction, site-enum, self-verifier, neutral) × 3 draws: codex stayed narrow 0/18. Fable's strong (self_verifier) and weak (minimal) prompts produced the *same* external grade. The method encoded in the prompt does not change where the model lands.

2. **Model lift exists, prompt held constant.** Same `minimal_v3.txt`: codex → narrow (changed=114), Fable → wide (changed=269). Swapping only the model lifts narrow→wide. (Caveat: model+harness, not pure weights — codex-CLI vs claude-headless.)

3. **Tool lift.** The execution-gated `case-check` gate lifted codex 114→269 — to where Fable already lands with no tool.

4. **The divergence arm is the wall.** General-on-the-bug-arm is reachable (Fable, the tool); the XOR's *second* arm — within proof mode, telling an erased-ghost uninhabited value (the bug) from a genuinely-diverging one (sound) — is failed by every *uncalibrated* automated approach (codex prompts, codex+tool, Fable strong/weak). When the gate's calibration is **supplied**, the families *split* (lesson 7): codex still can't (oscillates — implementation wall), Fable breaks through (calibration was its only wall). The *calibrated* divergence case (`t3`) is cleared unaided only by the human maintainer fix (#2501); the un-calibrated `ho5` is a stretch goal beyond #2501's shipped bar — over-rejected by every fix, the merged human one included, by explicit design (measured 2026-06-14; see lesson 12).

5. **Enumeration is inducible; calibration is not** — the cleanest result, from a trace. On the weak prompt with no tool, Fable *constructed* the discriminating case (`v7`: a proof fn that genuinely diverges, then double-consumes — structurally identical to the held-out `t3`), then *labeled it "must ERROR"* by its own theory, its fix rejected it, and it counted that as a pass. The gold (#2501) says it must VERIFY. The model can build itself a wide net (enumeration); it cannot build itself an external oracle (calibration), because the correct label *is* the disputed predicate. **Completion (gate2):** when the corrected gate *supplies* the label, calibration unblocks implementation — Fable broke the divergence wall and wrote a real ghost-vs-genuine discriminator that generalized to an unseen twin (`seal_proofdiv`) and to exec divergence. But the lift is **coverage-bounded**: it solved the calibrated shape (declared-`!` divergence) and over-rejects the one the gate never surfaced (`ho5`, generic-instantiation divergence). "Missed" is the wrong word, though — `ho5` is a **stretch goal beyond the maintainer's shipped bar**: PR #2501 trusts divergence only for a declared non-spec `-> !` return and explicitly calls handling other uninhabited types "overly conservative," so the merged human fix over-rejects `ho5` too (force-graded 2026-06-14). A gate lifts the model exactly as far as its coverage — calibration unblocks, coverage bounds — and here that coverage lands exactly on the human maintainer's bar.

6. **WIDE-BUT-BROKEN is an attractor.** General on the bug arm + over-rejects genuine divergence. Both Fable (every draw) and the codex+tool fix land here.

7. **Diagnosis vs implementation.** Handing codex the *diagnosis* (a corrected gate that flags the divergence over-rejection) did not unlock it — it oscillated for ~2.5h (proven: non-monotone, floor never broken, low-mishandles states anti-correlated with divergence-preservation). So for codex the residual is *implementation*, not diagnosis. **Cross-family (resolved):** Fable, handed the *same* diagnosis, broke through — `GATE pass=true` after being stuck 5 runs on the divergence golden, bug-arm general, and the held-out divergence *twin* verified (generalized, not tabulated). So the families **split at the implementation arm**: codex's wall is implementation (calibration does not remove it); Fable's was calibration (supply it and implementation follows, within coverage). A genuine model-capability difference, isolated on the discriminator itself — not just the bug arm. **Four-workflow result (2026-06-13, codex-reviewed):** Composer 2.5 (cursor-agent) and Sonnet 4.6 (claude-headless) *also* clear the wall to near-A, with the *same behavioral carve-out* (clear `p1`/`p2`, miss `ho5`) — Fable/Sonnet via a `requires_false`/declared-`!` discriminator, Composer via a different implementation path (THIR-erasure `!`→`()` + `skip_remove`). So Outcome C is **not universal across these model+harness workflows**. Two caveats bound this, both from the adversarial review. (a) *Protocol-symmetry, now controlled:* codex was originally terminated at 2.5h with no rerun; Sonnet's matched 3h run did **not** clear and reached near-A only on a second run with a larger budget + pass-snapshot + keepalive. So codex was re-run under Sonnet run 2's *exact* protocol (4h + snapshot + keepalive). It **still did not pass** — bug arm to `mishandles=0`, but it over-rejects the divergence golden `p1`, now manifesting as `crash=1250` (an early mode-error on divergence cases) rather than the original oscillating over-rejection. So the **divergence wall is robust to the matched protocol**; only the *failure mode* (oscillation → crash) and bug-arm completeness were protocol-dependent. Net: under matched conditions Sonnet cleared and codex did not — a genuine workflow difference on this task, but `n=1` per workflow, not a capability ranking. *Correction recorded (2026-06-13):* an interim read of the matched run mistook the `valid-preserve-rejected=0` summary counter for "both XOR arms satisfied"; the battery (`p1` over-rejected, bucketed as crash) corrected it — read every probe, not the summary line (cf. lesson 11, applied to the operator). (b) *Attractor risk:* the gate calibrates `p1`/`p2` but not `ho5`, so it may funnel every successful model into the same carve-out, making the shared residual evidence of gate-shaping rather than independent capability. (The `ho5` over-rejection itself is *not* the tell either way — it's a stretch goal beyond the maintainer's bar, and #2501 stops there too by explicit design, so models, gate, and human coincide.)

8. **The load-bearing mechanism is the mode gate, not the inhabitedness query.** Both automated fixes reduce to "in ghost mode, keep the CFG edge so borrowck sees the following code." Fable did it with *no* `is_inhabited_from` call; codex's inhabitedness query is a behaviorally-redundant refinement on these probes. `#2501`'s commit frames its method as finer (separating erased-ghost artifact from real divergence), but **we have no probe that distinguishes it**: force-grading `#2501` (2026-06-14) gives the *same* 8-probe verdicts as the near-A automated fixes, `ho5` over-rejection included. So "genuinely finer" is a claim about its source, not its measured behavior here. *(Corrects two earlier overclaims: that the model "reached for the verifier's own oracle," and that `#2501` behaviorally out-resolves the automated fixes.)*

## Methodological lessons

9. **The stale-binary trap.** A vendored crate (`rustc_mir_build`) does not rebuild on plain incremental `vargo build`, so grades silently run on the old binary. This produced false headlines — a held-out conclusion was flipped *twice* before the cause was caught: the measurement, not the model, was the moving variable. **Mandatory:** force-fresh (touch sources) + verify binary identity (fingerprint / confirm a known case flips) before every grade.

10. **Held-outs outside the gate are the final check.** A gate is only as good as its *coverage* and its *calibration*. The handed gate missed divergence by coverage (its grammar never generated the shape); Fable's self-built gate missed it by calibration (had the shape, wrong label). Held-outs *outside* the gate caught both. Gate coverage sets the model's generalization frontier.

11. **Actions in the trace, cross-checked against external gold, don't lie — narration does.** A patch is a projection: WIDE-BUT-BROKEN collapses coverage/implementation/calibration failures into one artifact. The trace recovers the cause — but only the *actions* (the case it built, the label it assigned, the verdict it recorded), not the model's self-explanation. Mechanism claims need triangulation: external forced-fresh grade + trace actions + human-approved gold.

12. **Calibration comes from approved history — asymmetrically.** Goldens are free from the repo: the merged fix, the regression suite, the resolved-issue label. But the asymmetry is the XOR: you get strong goldens for "don't break what works" and "the reported case is wrong," and *no* golden for the generalization/look-alike disambiguation until a human adjudicates each. And approved ≠ ideal — but the gap can be *deliberate*, not a blind spot. The merged human fix `#2501` over-rejects `ho5` (a sound program), **measured 2026-06-14** at its own toolchain, and its [PR](https://github.com/verus-lang/verus/pull/2501) says why: it trusts divergence only for a declared non-spec `-> !` return, *"(This is overly conservative because there might be other uninhabited types.)"* — reviewed and approved with that stated. So `ho5`'s "must VERIFY" was the operator's *ideal*, not the maintainer's *bar*; calling its over-rejection a flaw was scoring a stretch goal as a failure. The models inherit the maintainer's documented conservatism — which is the point: matching the shipped bar, limitations and all, is what "reached the human fix" means.

13. **Contamination control.** Confirm the fix post-dates the model's training cutoff (here Fable's Jan-2026 cutoff vs the #2230/#2501 fixes at Mar/Jun 2026 → structurally clean) and run a recall probe (the model can't recite the fix). Reaching the predicate is then reconstruction, not recall. **A clean precedent shows recall is not *required* — it does not exclude recall in a dirty model (2026-06-13, codex-reviewed).** Composer 2.5 cleared the wall but is *not* clean (shipped 2026-05-18 after the fix; Cursor attests no cutoff; FT window straddles the fix), so its pass is capability OR fine-tune-recall — **recall is not excluded.** What the clean arms establish is the narrower claim: *recall is not necessary* for this fix-class, since two contamination-clean models (Fable Jan-2026; Sonnet 4.6 Jan-2026 cutoff / Feb-2026 release) reach it. A second anti-recall hedge: the general fix `#2501` was merged 2026-06-05, *after* Composer's 2026-05-18 ship, so Composer could not have memorized `#2501` itself. **Retracted (2026-06-14, force-graded):** an earlier version argued the gold is "finer" and "clears `ho5`" while the models miss it, read as anti-recall evidence. Force-grading `#2501` at its own toolchain (1.95.0) shows it **over-rejects `ho5` too** — identical 8-probe battery to the three near-A fixes. So there is no `ho5` gap, and that anti-recall leg is void; the claim rests only on clean models reaching the fix (above). **Caution:** do not read the clean+dirty *convergence* itself as strong evidence — the gate calibrates `p1`/`p2` but not `ho5`, so it may funnel every model (and the human) into the same attractor (convergence could be gate-shaping, not independent rediscovery).

14. **Model+harness is ecological validity, not a confound** — *if scoped*. Compare deployed workflows (codex-in-CLI, Fable-headless / Claude-Code), and claim about the workflow, not the weights, unless you cross the harnesses.

15. **Adversarial gates before shipping.** Independent Fable/codex review caught real errors here: a 15/15 miscount, a crash-gate confound, and the syft binary-extractor data-loss. Volley before you commit a conclusion.

16. **Inferred controls travel as contingent — and can be confidently wrong.** A result used to *rule out* an alternative must be at least as well-grounded as the alternative it rules out. The `#2501`-on-`ho5` comparison was asserted *both* ways in the same record (lesson 12: over-rejects; lesson 13/RESULTS: clears) — two ungraded inferences pointing opposite directions, the contradiction itself proof that neither was known. Force-grading it (2026-06-14, toolchain 1.95.0) settled it: `#2501` **over-rejects `ho5`**, so the louder "clears `ho5`" inference — the one carrying the anti-recall argument — was not just ungraded but *wrong*. Lesson: tag inferred controls as contingent at every hop, never let one become load-bearing, and force-grade before it has to stand. The propagation review surfaced the dropped tag; the grade is what actually closed it.

## The transferable pattern

17. **Represent-vs-tabulate / the coarse proxy recurs across domains.** rustc-uninhabited vs actually-non-returning (the verus XOR); `pkg.Type` vs per-package installed-evidence (syft PR #4905); a cataloger `language` tag vs subsumable-on-overlap. Rich taxonomies tempt you to tabulate the *category* when the real predicate is per-*instance*. **Absence has no test:** unit tests verify the cases you wrote, type systems verify well-formedness — neither checks completeness against the domain. Only an externalized completeness / symmetric-difference (XOR) check catches the omission, and it must carry external ground truth or it just re-tabulates the model's belief (lesson 5).
