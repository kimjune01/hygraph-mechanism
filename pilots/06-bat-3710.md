# Pilot 06 - sharkdp/bat #3710 (--decorations=auto leaks decorations when piped) - NULL

First localization-region attempt (open bug, warm Rust repo, clean deterministic oracle).
Two arms parallel on one box (cubebox), separate trees (~/bat min, ~/bat_m +M), codex 5.5,
no golden (oracle = piped output has no decorations under --decorations=auto, with anti-gaming
guards: --decorations=always piped MUST keep them; content preserved).

## Localization assessment (honest)
Rated MODERATE, not strong. The blind graph (217 lines) correctly found the cause is NOT in
the printer where the symptom (decorations) appears, but in app.rs config-building: the
--decorations=auto value is parsed (clap_app.rs:307) but never wired as a gate; --color=always
forces loop_through off (app.rs:441), dragging decorations on. Fix shape predicted: separate
decoration gating from color gating, decorations_enabled = always || (auto && interactive_output).
BUT the issue body hinted at the structure ("--decorations controls WHEN, --style controls HOW"),
and it's a contained CLI-option-logic bug -> grepping `decorations` in app.rs localizes it.

## Result: NULL (both arms produced correct fixes)

| arm | oracle | fix |
|---|---|---|
| minimal (mini-SWE-agent) | PASS | added `decorations_enabled()` gate (always/never/auto->interactive_output), applied in forced_style_components + default resolution. 19 LOC. EXACTLY the graph's predicted fix. |
| +M (graph) | PASS | same gating idea, more thorough. 38 LOC. |

Both correct, both pass the anti-gaming oracle. The minimal agent found the missing gate (app.rs,
not the printer) and handled always/never/auto correctly, unaided.
