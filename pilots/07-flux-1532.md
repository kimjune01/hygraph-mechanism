The hard-region attempt: a refinement-type-checker ICE, in a domain (sort elaboration) far

## Protocol corrections (the durable result of this stretch)
1. **No gate.** Prior pilots handed the minimal agent our grading oracle and let it iterate to
   green - a strictly stronger agent than the baseline it represents, and likely why 6/6 nulled
   with no minimal-failure. Here the minimal agent got ONLY the verbatim issue + repo, no oracle,
   and submitted when it believed it was done (faithful mini-SWE-agent).
2. **No pre-digested diagnosis.** Earlier I editorialized the recon prompt ("the program is VALID,
   look at conv/mod.rs"). Here both arms get the verbatim issue; the diagnosis (including the
   accept-vs-reject judgment) must be EARNED from repo + raw issue.
3. **Harness output is its existing PR, for merged-pool instances** - so the experiment is
   one-armed: run minimal, blind-judge its (fix+test) against the harness's. For flux (open, no
   PR) the harness arm is held in reserve, run only if minimal fails.
4. **Grade the (test+impl) COMBO**, blind, by an Opus+Codex panel, anchored by the objective
   accept-vs-suppress oracle. Convergence -> tie/null; divergence -> obvious winner.

## Result: NULL on the fix (minimal succeeded unaided)
Minimal's diff = the harness's prescribed fix: add `self.check_expr(&expr, &rty::Sort::Bool)` on
the `no_panic_if` expr in WF (`flux-fhir-analysis/src/wf/mod.rs`) + visit it in the FHIR traversal
(`flux-middle/src/fhir/visit.rs`). Evidence the reported ICE is cleared: in minimal's tree the
original program's error MOVED from `node without elaborated sort` (the bug, in conversion) to a
downstream `failed to run fixpoint` (SMT-backend) step. Minimal also put its test in `tests/pos/`
(expects acceptance) - so it navigated the suppression trap (reject the valid program) correctly,
which the harness recon had to explicitly kill. No diagnosis needed; no existence case.

Residual (ungradeable here): TEST QUALITY. Minimal shipped a weakened `pos/` test
(`fn foo(_x){9}` - dropped the panic branch, 0 constraints, doesn't exercise no_panic_if
verification). The harness recon prescribed the full program + a companion `neg/` test (non-bool
condition -> sort error). A real edge, same shape as fjall #287's completeness edge: the graph's
value keeps landing in quality dimensions a binary oracle can't score, that a strong baseline gets
"adequate" on anyway.
