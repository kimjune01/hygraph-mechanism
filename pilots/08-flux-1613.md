The hardest, most maintainer-stuck bug we curated, run with the fully corrected protocol AND

## Setup (rigorous)

- Anti-false-positive oracle: target program must verify AND the neg-test suite must still reject

## Result: minimal SUCCEEDED, soundly
The no-gate minimal agent (GPT-5.5 / mini-SWE-agent) fixed it: target verifies, FULL suite
passes (965 tests, 0 failed - neg still rejects, pos still verifies), shipped both a pos and a
neg test. The fix introduces a general `LocKind::Reborrow` mechanism (block the place behind a
&mut field with a function-sort refinement, track the reborrow, re-hoist the updated type on
unblock) in the FIXME-marked branch flux's own author flagged as incomplete. 8th instance, 8th
time minimal did NOT fail. Baseline reach held even on a 41-comment type-checker bug.

## Quality: blind dual-judge SPLIT (the first genuinely contested result)
Opus + Codex, blind, labels stripped, told to hunt false positives:
- **Codex: FALSE-POSITIVE** - the `needs_tracked_reborrow` gate (ADT with a `Sort::Func` field)
  is an over-narrow shape-special-case; bypasses general place-unblocking.
- **Opus: CORRECT-PRINCIPLED** - faithful transplant of flux's own `ptr_to_ref`/`LocalPtr`

  condition (predicate sorts get havoc'd under a weak update, int indices survive), can only opt
  into stricter tracking so cannot become unsound.

## The decisive methodological correction (operator)
Quality is meaningless without RECEIPTS. The judge split is OPINION. "Over-narrow" is a
HYPOTHESIS, real only if there is a concrete discriminating program: a valid mutable-reborrow of
a non-function-sort struct that minimal's fix wrongly rejects (or an invalid one it wrongly
accepts) that a general fix would handle. If no such program exists, the critique is vacuous and
the fixes are behaviorally identical. RECEIPTS were NOT built (the harness comparison arm crashed
mid-investigation, ~1 round of exploration then codex died; no fix produced). So the quality
difference is UNSETTLED, not "the harness wins."

## Verdict (codex's knife, the defensible claim)
The explicit hypothesis graph has NOT earned its complexity. On 8 real bugs incl. hard ones, no
pass/fail advantage over a minimal agent on the same model. Not "super effective," not "inert."
Any remaining value claim must move to (a) a preregistered harder regime with a predicted minimal-
failure, (b) an efficiency/auditability metric, or (c) a receipt-backed quality difference - none
of which this un-preregistered run established.

## The real payoff of the session: see METHODOLOGY-preregistration.md
Pre-registration is the DEDUCTION rung of Peirce's abduction->deduction->induction, not a
statistical tool. We ran 8 inductive loops with zero deductive rungs (no per-loop predictions),
so every null retrofitted into a new abduction (harder / quality / receipts) instead of testing.
Deduction cadence must match abduction cadence: pre-register PER LOOP (one sentence: testing X,
predict Y, refuted by Z), not in a big chunk. The harness crash here is the lesson live - launched
as a next-abduction generator with no deduction, so it could only suggest, never settle.
