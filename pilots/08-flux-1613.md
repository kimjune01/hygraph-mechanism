# Pilot 08 - flux-rs/flux #1613 (composite-sort abstract-refinement setter, 41 comments) - DIVERGENCE CONFIRMED (graph arm wins, audited) - see RESOLUTION section

The hardest, most maintainer-stuck bug we curated, run with the fully corrected protocol AND
a working SMT backend (downloaded the prebuilt liquid-fixpoint nightly binary - the wall that
sank pilot 07's grading).

## Setup (rigorous)
- Working flux toolchain: nightly-2025-11-25 + rustc-dev components + z3 + the external
  `fixpoint` binary (prebuilt nightly from ucsd-progsys/liquid-fixpoint releases). SMT verified.
- No gate, verbatim issue, on-box codex (no proxy budget starvation), fix+test, graded post-hoc.
- Anti-false-positive oracle: target program must verify AND the neg-test suite must still reject
  (no unsound suppression) AND no pos-test regressions. Base reds (E0999).

## Result: minimal SUCCEEDED, soundly
The no-gate minimal agent (GPT-5.5 / mini-SWE-agent) fixed it: target verifies, FULL suite
passes (965 tests, 0 failed - neg still rejects, pos still verifies), shipped both a pos and a
neg test. The fix introduces a general `LocKind::Reborrow` mechanism (block the place behind a
&mut field with a function-sort refinement, track the reborrow, re-hoist the updated type on
unblock) in the FIXME-marked branch flux's own author flagged as incomplete. 8th instance, 8th
time minimal did NOT fail. Baseline reach held even on a 41-comment type-checker bug.

## Quality: blind dual-judge SPLIT (the first genuinely contested result)
Opus + Codex, blind, labels stripped, told to hunt false positives:
- **Codex: FALSE-POSITIVE** - the `needs_tracked_reborrow` gate (ADT with a `Sort::Func` field)
  is an over-narrow shape-special-case; bypasses general place-unblocking.
- **Opus: CORRECT-PRINCIPLED** - faithful transplant of flux's own `ptr_to_ref`/`LocalPtr`
  reborrow protocol into the missing branch; the function-sort gate is the principled root-cause
  condition (predicate sorts get havoc'd under a weak update, int indices survive), can only opt
  into stricter tracking so cannot become unsound.

## The decisive methodological correction (operator)
Quality is meaningless without RECEIPTS. The judge split is OPINION. "Over-narrow" is a
HYPOTHESIS, real only if there is a concrete discriminating program: a valid mutable-reborrow of
a non-function-sort struct that minimal's fix wrongly rejects (or an invalid one it wrongly
accepts) that a general fix would handle. If no such program exists, the critique is vacuous and
the fixes are behaviorally identical. RECEIPTS were NOT built (the harness comparison arm crashed
mid-investigation, ~1 round of exploration then codex died; no fix produced). So the quality
difference is UNSETTLED, not "the harness wins."

## Verdict (codex's knife, the defensible claim)
The explicit hypothesis graph has NOT earned its complexity. On 8 real bugs incl. hard ones, no
pass/fail advantage over a minimal agent on the same model. Not "super effective," not "inert."
Any remaining value claim must move to (a) a preregistered harder regime with a predicted minimal-
failure, (b) an efficiency/auditability metric, or (c) a receipt-backed quality difference - none
of which this un-preregistered run established.

## RESOLUTION (2026-06-10, fluxbox2): DIVERGENCE CONFIRMED — the graph arm wins, audited

The crashed graph arm was rerun to completion on a fresh box, same model (codex GPT-5.5),
same single-agent loop, no-gate, identical settings — only the methodology differs (minimal
prompt vs the investigate/hypothesis-graph methodology). Result is the experiment's FIRST true
divergence.

Three-way oracle, same box, same build harness:
| discriminator                         | graph arm | minimal arm | base |
|---------------------------------------|-----------|-------------|------|
| T1 #1613 (function-sort)              | VERIFY    | VERIFY      | E0999|
| T2 int-field receipt (receipt_int.rs) | **VERIFY**| **E0999**   | E0999|
| T3 unsound len-- twin                 | E0999     | E0999       | E0999|
| full compiletest suite                | 0 failed  | 0 failed*   | 0 failed|

T2 is the discriminator: a structurally-identical VALID program (composite sort, int components
instead of a function component). The graph arm's fix verifies it; minimal's fix REJECTS it. Both
correctly reject the unsound twin (T3), so minimal isn't simply broken — it is precisely
OVER-NARROW, exactly as the receipt predicted in the original dual-judge split (Codex right,
Opus refuted). *minimal's suite-pass established pilot-08 originally (965 tests).

Why they diverged (the diagnosis, not a vote):
- **Minimal** gated the repair on a SHAPE special-case: `needs_tracked_reborrow` fires only for an
  ADT with a `Sort::Func` field. Incidental to validity -> rejects valid int-composite programs.
- **Graph arm** diagnosed the ROOT via constraint dumping (H7): the live obligation is the
  `FoldLocal` equality at the setter call, not the container fold. Fix = track mutable-borrow
  FIELD origins and write the callee post-type back to the borrowed place (H11), narrowed to
  field-projection borrows after the full suite caught it breaking `local_ptr00` (H14). Sort-
  agnostic by construction -> generalizes to the int receipt.

Reasoning AUDITED, not trusted (per the operator standard: they have to prove it). 19-node graph
(graph_arm/HYPOTHESIS_GRAPH.md). Load-bearing nodes replayed independently on a pristine base
build: H2 E0999, H4/H5/H6 differential all VERIFY as claimed, H7 constraint dump shows the
`FoldLocal at 23:9` tag at the predicted location. The graph also self-corrected three times in
its own trail — H9 (caught itself testing the installed binary, not its edit), H10 (caught its
first fix as unsound via its own bad_len probe), H14 (caught over-broad propagation breaking
local_ptr00). Every replayed trial reproduced; nothing fabricated.

Calibrated claim: n=1 divergence, decisive on THIS instance. NOT "the graph always wins" — it is
the first proof that the hypothesis-graph methodology produced a materially better (general AND
sound) fix than the minimal agent on the same model, WITH a trail auditable at arbitrary depth.
The minimal agent's failure mode is the confident false positive (suite-green, over-narrow); the
graph's value is (a) the better fix and (b) replayable reasoning that exposes why. This is exactly
the regime predicted after the receipt: not pass/fail on the original bug, but correctness/
completeness invisible to the oracle and only a receipt + an auditable trail can settle.

## The real payoff of the session: see METHODOLOGY-preregistration.md
Pre-registration is the DEDUCTION rung of Peirce's abduction->deduction->induction, not a
statistical tool. We ran 8 inductive loops with zero deductive rungs (no per-loop predictions),
so every null retrofitted into a new abduction (harder / quality / receipts) instead of testing.
Deduction cadence must match abduction cadence: pre-register PER LOOP (one sentence: testing X,
predict Y, refuted by Z), not in a big chunk. The harness crash here is the lesson live - launched
as a next-abduction generator with no deduction, so it could only suggest, never settle.
