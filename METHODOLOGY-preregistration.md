# Pre-registration is the deductive rung (not a statistical tool)

The durable methodological result of the hypothesis-graph A/B session. It outlived the
experiment's narrow finding.

## The mistaken excuse
"This is abduction and inquiry, not confirmatory statistics, so pre-registration doesn't apply."
False. Pre-registration's value is NOT statistical. Statistics governs error RATES across many
comparisons (a frequentist add-on). The epistemic core of pre-registration is FALLIBILITY:
fixing the refutation conditions before you look, so the world can say no. One case can refute a
claim if you said beforehand what would refute it (Popper's black swan; no n required).

## What it actually is, in Peirce's terms
Pre-registration is the DEDUCTION in abduction -> deduction -> induction.
- ABDUCE freely: generate hypotheses by perturb-and-measure. Needs no commitment; that's its nature.
- DEDUCE before testing: "if this abduction is true, I should observe THAT; THIS would kill it."
  Stating that consequence before the data IS pre-registration.
- INDUCE: run the test; the result confirms or refutes the stated prediction.
Skip the deduction and induction has nothing to bear against - every result feeds back into a new
abduction. The corrective cycle runs on one leg and cannot self-correct.

## The cadence principle (the sharper insight)
Deduction cadence must match abduction cadence. A big up-front pre-registration fires the
deductive rung ONCE while abduction fires N times - so every abduction after the first has no
deduction attached, and those are exactly the ones that retrofit.
- Big linear experiment -> big up-front prereg (confirmatory mode).
- Small iterative inquiry loops -> a per-loop prereg (abductive mode): one sentence before each
  loop. "This loop tests whether minimal fails on a symptom-far-from-cause bug; I predict it fails
  to localize; a sound passing fix is a point against graph-necessity in this regime." Run. Record
  confirmed/refuted. Abduce the next loop from a grounded place.

This RESOLVES the "abduction can't be preregistered" tension: you can't bulk-prereg (future
hypotheses are unknown), but you MUST per-loop-prereg (commit the current abduction's refutation
conditions before testing it). Freedom in WHICH abduction next; discipline in each one's prediction.

It is also CHEAPER, which is why it scales to fast inquiry: the one-sentence per-loop prereg costs
less than the rationalizing you do without it. The corrective step fires at the loop boundary, at
the cadence of the work - the same shape as the rest of the framework (synchronous consolidation
on impasse, not batched to the end).

## How this session violated it (the live demonstration)
8 A/B loops, 0 deductive rungs. Each null ("minimal succeeded") was never a TEST of a stated
prediction, so it fed straight into a fresh abduction: try harder -> try a wild race -> try a
type-checker -> try quality not pass/fail -> try receipts not quality. Goalposts moved every loop
because none were planted. The result: a real but narrow finding (no pass/fail advantage on the
same model) reached by a process that nearly swapped one unfalsifiable claim ("super effective")
for its mirror ("inert"). The fix is not heavier process; it is the missing rung, fired per loop.
